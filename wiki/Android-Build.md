# Android Build

How the Android app is built, what is hand-edited in the generated project (so it survives a
regeneration), signing, and the dev loop. Target: **arm64** tablets (verified on a Xiaomi Pad,
Android 14 / API 34).

## Toolchain (what this was built with)

| Piece | Version |
|-------|---------|
| JDK | 21 (IntelliJ's bundled JBR; any JDK 17+ works) |
| Android SDK | platforms `android-36` and `android-37.0` (the generated project uses `compileSdk 37`), build-tools `36.0.0` + `37.0.0`, platform-tools |
| NDK | `28.0.13004108` (`NDK_HOME`) |
| Rust targets | `aarch64-linux-android` (+ `armv7`, `i686`, `x86_64`, which `tauri android init` adds) |
| Generated by | Tauri CLI 2.12.1: Gradle 9.6.1, AGP 9.3.1, Kotlin 2.2.10, `android.builtInKotlin=false` |

Set `ANDROID_HOME`, `NDK_HOME` and `JAVA_HOME`. The first Gradle run downloads Gradle and the
AndroidX/CameraX artifacts.

## `gen/android` is committed — and hand-edited

`bun x tauri android init` creates `src-tauri/gen/android`; it is meant to be committed. These
edits are **not** regenerated, so re-apply them if you ever re-run `init`:

| File | Edit | Why |
|------|------|-----|
| `app/src/main/AndroidManifest.xml` | `<uses-feature android.hardware.usb.host required="false">` | The Sony is a USB device the tablet hosts; optional so the app still installs elsewhere |
| same | `USB_DEVICE_ATTACHED` intent filter + `<meta-data … @xml/device_filter>` on the main activity | Plugging in the camera offers to open the booth, and "always open" grants USB permission without a dialog |
| `app/src/main/res/xml/device_filter.xml` (new) | `<usb-device vendor-id="1356" />` | `1356` is `0x054C`, Sony, in decimal (the filter requires decimal) |
| `app/build.gradle.kts` | `signingConfigs` reading `keystore.properties` | Release/upload signing with secrets kept out of git (below) |
| `app/src/debug/res/values/strings.xml` (new) | launcher label "Photobooth (Tauri)" | Tells the two apps apart on the tablet |
| `.gitignore` | `*.jks`, `*.keystore` | Never commit a keystore (`keystore.properties` is already ignored) |

**Not a hand-edit — the debug application-id suffix.** Debug builds install **beside** the existing
Kotlin app (same base id, different signing key) instead of failing with
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`. It is set with `bundle.android.debugApplicationIdSuffix`
(`".tauri"`) in `tauri.conf.json`; the Tauri CLI writes it into `app/build.gradle.kts` on every
build and **deletes a hand-edited line** — which is how this was found (a hand-edit worked for one
build, then silently vanished and the APK collided with the existing app again). The launcher label
("Photobooth (Tauri)") comes from the debug source set listed above.

The camera permission and `uses-feature camera` come from the **plugin's** manifest and are merged
automatically; `INTERNET` is Tauri's default.

**Deviation: no `android:keepScreenOn`.** It is a *view* attribute, not an `<activity>` attribute,
so it cannot go in the manifest. Keep-awake is instead set at runtime
(`FLAG_KEEP_SCREEN_ON`) by the booth screen through the plugin's `windowSetKeepScreenOn`, and
cleared when the booth screen closes — so the tablet still sleeps on the picker.

## Signing

Debug builds use Android's standard debug key automatically. For a release/upload build, create a
keystore **locally** and keep it out of git:

```bash
keytool -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
```

then create `src-tauri/gen/android/keystore.properties` (gitignored):

```properties
storeFile=../../../upload.jks
storePassword=…
keyAlias=upload
keyPassword=…
```

Without that file a release build is simply unsigned. No keystore is committed or generated by
this repo.

## Building

**With Developer Mode** (Windows: Settings → System → For developers) or on macOS/Linux:

```bash
cd apps/booth
bun x tauri android build --apk --debug --ci --target aarch64 --config src-tauri/tauri.dev.conf.json
```

`--config …tauri.dev.conf.json` includes the **dev** capability so the test-mode developer panel
works in the APK; omit it for a build that behaves like release.

**Windows without Developer Mode:** the CLI compiles the Rust library and then tries to
**symlink** it into Gradle, which Windows forbids without that setting. Rather than change a system
setting, `apps/booth/scripts/build-android-debug.ps1` lets the CLI compile, copies the library into
`jniLibs` instead, and runs Gradle with the Rust tasks skipped:

```powershell
apps\booth\scripts\build-android-debug.ps1 -Install   # builds, then adb install -r
```

### Windows gotchas hit while building this

- **Use `bun x tauri …`, not `bun tauri …` / `bun run tauri …`.** `bun run` sets `npm_execpath`
  to an *empty string*, and the Tauri CLI panics in `android init`
  (`mobile/init.rs: Option::unwrap() on None`). `bun x` does not.
- The symlink restriction above. It also affects `tauri android dev` unless Developer Mode is on.
- `sdkmanager`'s package id for platform 37 is `platforms;android-37.0`, not `android-37`.
- The same `com.jc.photobooth` id on the tablet comes from the existing Kotlin app — see the
  `.tauri` suffix above. **Do not uninstall it** to make room.

## Dev loop

```bash
cd apps/booth
bun x tauri android dev --host --config src-tauri/tauri.dev.conf.json   # needs Developer Mode on Windows
```

`--host` makes the Bun dev server listen on the LAN (`TAURI_DEV_HOST`) so the tablet reaches it;
`bun run dev` streams the WebView's `console.log` to the terminal. For WebView debugging open
`chrome://inspect` on the dev machine with the tablet attached (debug builds enable WebView
debugging). Rust logs: `adb logcat -s Photobooth`.

## CI

`.github/workflows/ci.yml` runs Rust fmt/clippy/test, the frontend typecheck/tests/build, and — once
`gen/android` is committed — builds the debug APK on `ubuntu-latest` and uploads it as an artifact.
There are no cloud device farms; running the APK on the tablet is manual.

## Known limitations

- `bun x tauri android dev` and `build` need Developer Mode on Windows (or the script above for
  builds).
- The debug APK is large (~140 MB) because the native library keeps debug symbols; release builds
  strip it.
- `tauri.dev.conf.json` is also used for APK builds only to enable the dev capability; its
  `devCsp` is ignored outside `dev`.
